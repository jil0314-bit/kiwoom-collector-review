# 방송·유튜브 추천 화면 수정 (2026-11-08)

## 확인한 원인
- 11/8 실제 API에는 165건(65종목)이 있지만 모두 단순 언급이다. 기본 신규추천 필터가 0건으로 숨겨 자료 전체가 없는 것처럼 보였다.
- 11/8 원문 95개 중 자막 관련 확인 필요 93개. 자막 응답 실패는 자막 자체가 없다는 증거가 아니다. 발언을 읽지 못한 자료는 추천으로 승격하지 않는다.
- 11/6에는 확인된 신규추천 9건이 저장돼 있다. 최근 신규추천 버튼으로 실제 표시했다.
- 보조 시총·테마 요청을 기다린 다음 목록을 렌더링하던 의존성을 제거했다.
- 공통 테이블 최소폭 700px이 약635px 목록 패널을 넘어 가로 스크롤이 생겼다. 이 페이지에만 최소폭 해제를 적용했다.

## 변경 범위
web/recommendations.html, web/recommendations.js, web/recommendations.css 및 관련 회귀검사·이 문서·manifest만 수정한다. 수집 추출 규칙·매매·주문·0600·다른 탭·개인 메모는 변경하지 않았다.
전체 기본 표시, 분류별 수량, 날짜별 신규추천 탐색, 자막/출처 확인 필요 수량, 목록 새로고침, 통신 오류 안내, 지연된 보조 요청과 목록 표시 분리, 작은 화면 목록 우선 배치를 추가했다. 최근 신규추천 버튼은 저장 자료만 탐색하며 수집을 실행하지 않는다.

## 검증
- 추천 Python 기존 테스트 28개 통과.
- 공통 0600 재시도 검사 통과.
- 추천 JS 문법, git diff --check 통과.
- 새 UI 테스트: 표본 응답의 전체/분류/날짜 전환, 자막 경고, 시총 조회 지연, 빈 결과, 720px/1415px 가로 넘침, API 오류 시 기존 목록 유지, 쓰기 요청 없음 통과.
- 실행 중인 실제 서버와 설치된 Edge의 분리된 브라우저 세션에서 11/8 165행, 최근 신규추천 11/6 9행 표시와 JS 오류 없음 확인. 1415px 목록 가로 넘침 없음. 실물 영웅문 전환 검사는 이번 화면 점검 범위가 아니다.
- 최초 통신을 사용한 UI 테스트에서는 일부 정적 JS 요청 net::ERR_CONNECTION_REFUSED가 관찰됐다. 실제 서버의 후속 3회 재조회에서는 재현되지 않았다. 이 간헐적 연결 실패의 원인은 확정하지 않았고 서버 전역 설정은 변경하지 않았다. 표본 회귀검사는 실제 소스 파일을 제공해 통신 장애와 화면 동작을 분리했다.

## 남은 한계와 예약
유튜브 공개 자막 수신 실패 자체는 해결됐다고 주장하지 않는다. 이를 단순 언급과 구분하고 공개 기사로 확인된 추천을 탐색할 수 있게 했다. 모든 영상 발언이 수집된다는 보장은 없다.
11/9 17:15 예약에는 자동 수집, 상승률 상위 실제 화면, 영웅문 실제 메모 읽어오기까지 확인하도록 추가했다. waiting_for_hero4_exit는 완료가 아니며 개인 메모 보존, 영웅문 임의 종료 금지, 문제 부분만 수정 및 GitHub 반영을 명시했다.
