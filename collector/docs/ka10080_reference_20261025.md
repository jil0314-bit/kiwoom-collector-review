# 사용자 제공 ka10080 분봉 예제 참고 — 2026-10-25

사용자가 제공한 requests 기반 예제의 유용한 계약과 향후 활용 원칙을 보존한다.
기존 수집기·자동매매·주문 코드는 변경하지 않았다. 실행용 배포 ZIP에 넣을 필수 파일은 아니다.

## 확인한 API 계약

키움 스펙 도구 `spec_show(api_id="ka10080")`로 2026-10-25 확인.

- POST `https://api.kiwoom.com/api/dostk/chart`, `api-id: ka10080`.
- `authorization: Bearer <token>`: 토큰 문자열에 Bearer를 중복으로 붙이지 않는다.
- `stk_cd`: KRX `005930`, NXT `005930_NX`, 통합 `005930_AL`.
- `tic_scope`: `1`, `3`, `5`, `10`, `15`, `30`, `45`, `60`분.
- `upd_stkpc_tp`: 수정주가 구분 `0` 또는 `1`. 기존 수집기는 `0`을 사용한다.
- `base_dt`: 선택 필드, `YYYYMMDD`. 사용자 예시 `20260629`는 고정된 예시 날짜이며 현재 날짜가 아니다.
- 응답 헤더 `cont-yn == Y`이면 `next-key`로 추가 조회한다. 예제처럼 한 번 더 조회하는 것만으로 전체 이력을 받았다고 볼 수 없다.

## 사용자 예제의 최소 정리본

탭/공백 혼용을 정리하고 통신 제한시간·HTTP 오류 확인을 추가했다.
아래 코드는 참고 문서 안의 함수 정의이며 자동 실행하지 않는다. 실제 토큰을 문서·코드·로그에 저장하지 않는다.

```python
import requests

def fn_ka10080(token, data, cont_yn="N", next_key=""):
    response = requests.post(
        "https://api.kiwoom.com/api/dostk/chart",
        headers={
            "Content-Type": "application/json;charset=UTF-8",
            "authorization": f"Bearer {token}",
            "cont-yn": cont_yn,
            "next-key": next_key,
            "api-id": "ka10080",
        },
        json=data,
        timeout=(5, 30),
    )
    response.raise_for_status()
    payload = response.json()
    if str(payload.get("return_code", "")) != "0":
        raise RuntimeError("키움 분봉 조회 실패: 반환 코드를 확인하세요.")
    return response

# 호출자는 기존 인증 경로에서 받은 token을 전달한다.
# data = {
#     "stk_cd": "005930", "tic_scope": "1",
#     "upd_stkpc_tp": "1", "base_dt": "20260629",
# }
```

## 기존 구현과 향후 자동매매 활용

현재 `collector/kiwoom.py`의 `Kiwoom.minute_bars()`가 같은 API를 사용한다.
통합시장·비수정주가를 사용하며, 최대 40페이지 연속조회, 요청·응답 종목 일치,
시간 역순 정렬, 같은 시각 값 충돌, 키 반복, 날짜 범위 및 빈 응답을 검사한다.
새 예제로 기존 구현을 대체하거나 수정주가·거래소 설정을 조용히 변경하지 않는다.

향후 자동매매의 분봉·이동평균·거래량 분석에 참고할 수 있다. 적용 시에는:

1. 진행 중인 봉과 완료된 봉을 구분하고, 신호 시점 이후 데이터로 과거 신호를 계산하지 않는다.
2. 거래소·수정주가·주기·기준일을 전략 명세와 맞추고, 실제 반환 날짜를 확인한다.
3. 누락·중복·지연·호출 제한·연속조회 완료 여부를 검사한다.
4. 기존 명세에 맞춘 백테스트·PAPER 검증을 먼저 수행한다. 이 예제 저장은 실주문 실행 승인이 아니다.

조회 API 예제는 데이터 수집에 도움을 주지만 수익성이나 주문·체결 안정성을 검증하지 않는다.
