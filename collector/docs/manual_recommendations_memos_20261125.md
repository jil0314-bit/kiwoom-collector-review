# 직접 추천 등록 · 공통 메모 · 화면 정리 (2026-11-25)

## 사용 방법
- 방송·유튜브 추천 상단에서 종목명/코드를 검색하고 검색 결과를 선택한 뒤 `추천종목에 등록`을 누릅니다.
- 수집된 종목 여부와 관계없이 기존 전체 시장 종목 목록으로 검증합니다. 서버의 실제 한국 시각 입력일에 신규추천으로 저장하며, 같은 날 같은 종목은 중복 등록하지 않습니다.
- 등록 후 공통 메모장이 열립니다. 날짜를 확인하고 사유를 작성하여 `메모 저장`을 누릅니다.
- 모든 수집 탭의 종목명 오른쪽 삼각형으로 같은 개인 메모를 열 수 있습니다. 가장 최근 수정된 비어 있지 않은 메모를 이름 옆에 한 줄로 표시하고, 전체 내용은 메모장에서 확인합니다.
- 메모장은 저장 날짜를 명시합니다. 과거 메모를 열면 해당 날짜가 표시되며 날짜를 바꾸어 별도 메모를 작성할 수 있습니다. 저장 충돌 시 작성 내용을 유지하고 기존 저장본을 덮어쓰지 않습니다. `저장본 다시 읽기`는 작성 내용 폐기 확인 후 실행합니다.
- 날짜 목록은 가로 스크롤, 설명·수집 조건은 펼침으로 유지합니다. 창 높이가 작은 경우 제목 설명을 접고 차트에 공간을 배정합니다. 시계 크기와 차트 그리기·십자선·주문/수집 조건은 변경하지 않았습니다.

## 저장 계약
- `POST /api/recommendations/manual`: `{code}`. 기존 로컬 토큰 인증 필요. 전체 시장 목록에서 코드 검증, 서버 KST 입력일 사용, `recommendations/YYYY-MM-DD/index.json`에 기존 잠금/병합 함수로 저장합니다. 기존 자동 수집과 서로의 기록을 보존합니다.
- `GET /api/notes/latest?codes=005930,000660`: 최대 200종목의 최신 개인 메모. 날짜별 원본은 유지하며 읽기만 합니다.
- `POST /api/notes`: 기존 `{day,code,name,text,revision}` 계약 유지. 사용자와 자동화 모두 이 동일한 경로를 사용합니다. 충돌 응답은 409이며 다시 읽기 전 무조건 재시도하지 않습니다.
- 추천 등록과 메모 저장은 별도입니다. 메모 저장 실패 시에도 등록한 종목은 남으며 메모 작성 내용은 화면에 보존됩니다.

## 검증
- 관련 Python 회귀 81개 통과 후, 실제 임시 HTTP 서버의 인증/입력일/메모 저장·재조회 검증 1개 추가 통과(총 82개).
- 8개 탭의 공통 메모 표시·저장·충돌·차트 클릭 방지·좁은 화면을 합성 데이터로 검증했습니다. 방송 추천에서 과거 날짜를 보다가 직접 등록해도 서버 입력일로 이동하는 것을 검증했습니다.
- 기존 전체 시장 검색→차트→관찰종목, 방송 추천 필터/자료 보존, 차트 캐시 검증 통과.
- 운영 서버를 기존 예약 작업으로 재시작하여 새 조회 API 응답을 확인했습니다. 운영 화면 8개 탭에서 메모 버튼·화면 배치·브라우저 오류 여부를 읽기 전용으로 확인했습니다. 실제 개인 자료에는 시험 추천/메모를 추가하지 않았습니다.
- 이 작업은 실제 키움 0600 클릭이나 주문 전송 검증을 포함하지 않습니다. 장기 무오류를 보장한다는 의미가 아닙니다.
